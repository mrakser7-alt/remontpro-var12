# РемонтПро — сайт ремонтной компании

Учебный проект по варианту 12: корпоративный сайт компании «Профессиональный ремонт квартир и коттеджей» с личным кабинетом клиента и административной панелью.

**Сроки разработки:** 02.11.2026 — 14.11.2026

## Стек

- PHP 8.1+ (без фреймворка)
- SQLite 3 через PDO (режим WAL)
- HTML5, CSS3 (собственная дизайн-система), ванильный JavaScript
- Шрифт Manrope, иконки-иллюстрации — inline SVG

## Быстрый запуск

```bash
cd "var12 nov2026"
php -S 127.0.0.1:8000
```

Откройте <http://127.0.0.1:8000>.

При первом обращении база `data/database.sqlite` создаётся автоматически и заполняется демонстрационными данными (услуги, проекты, акции, отзывы, заявки, пользователи).

Перезаполнить базу с нуля:

```bash
rm -f data/database.sqlite data/database.sqlite-wal data/database.sqlite-shm
rm -rf data/cache/*
```

Требования: PHP с расширениями `pdo_sqlite`, `mbstring`; каталог `data/` должен быть доступен на запись.

### Запуск через Docker (рекомендуется на другом ПК)

Требуется только Docker Desktop или Docker Engine с Compose:

```bash
git clone https://github.com/mrakser7-alt/remontpro-var12.git
cd remontpro-var12
docker compose up --build
```

Откройте <http://localhost:8080>. База SQLite хранится в Docker volume и не пропадает при пересоздании контейнера. Остановить проект можно командой `docker compose down`.

## GitHub Pages

Статическая публичная витрина хранится в каталоге `docs/` и публикуется GitHub Pages из ветки `main`.

GitHub Pages не выполняет PHP и не поддерживает SQLite, поэтому на опубликованной витрине доступны страницы, навигация, стили и JavaScript-интерфейс, но отправка форм, регистрация, вход, личный кабинет и админ-панель работают только в полной версии при локальном запуске. Сборку витрины можно проверить локально:

```bash
bash scripts/build-pages.sh
php -S 127.0.0.1:8098 -t docs
```

После изменения PHP-шаблонов пересоберите `docs/`, закоммитьте результат и отправьте изменения в `main` — GitHub Pages обновит сайт.

## Роли и возможности

### Гость
- Все публичные страницы: главная, о компании, услуги, портфолио, отзывы, акции, контакты, команда проекта.
- Отправка заявки на ремонт и сообщения через форму обратной связи.
- Регистрация и вход.

### Клиент (`user`)
- Личный кабинет: обзор, история заявок со статусами, редактирование профиля, смена пароля.
- Подача заявки с привязкой к аккаунту.
- Оставление отзыва только после завершённого ремонта (есть хотя бы одна заявка в статусе «Выполнено»). Новый отзыв попадает на модерацию.

### Менеджер (`manager`)
- Обработка заявок: просмотр, смена статуса, комментарий менеджера, удаление.
- Просмотр и модерация отзывов.
- Доступ к статистике заявок.
- Нет доступа к управлению услугами, портфолио, акциями, пользователями и сообщениями (проверка и в меню, и по прямому URL).

### Администратор (`admin`)
- Полный доступ к панели управления.
- CRUD услуг, проектов портфолио и акций.
- Модерация отзывов (одобрение / отклонение / удаление).
- Управление пользователями и ролями.
- Просмотр сообщений обратной связи.
- Обработка заявок и сводная статистика.

## Безопасность

- Пароли — bcrypt (`password_hash` / `password_verify`).
- Защита всех изменяющих запросов через CSRF-токены.
- Экранирование вывода (`htmlspecialchars`).
- Подготовленные PDO-запросы (защита от SQL-инъекций).
- Honeypot-поле и ограничение частоты отправки форм (антиспам).
- Проверка ролей на сервере, а не только скрытие пунктов меню.
- Cookie сессии: `HttpOnly`, `SameSite=Lax`.
- Заголовки `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`.
- Валидация и нормализация пользовательского ввода на сервере.

## Производительность

- SQLite в режиме WAL, подготовленные запросы.
- Файловый кеш для редко меняющихся выборок (`data/cache`).
- Ленивые изображения и inline SVG вместо тяжёлых фото.
- Ограничение анимаций при `prefers-reduced-motion`.

## Адаптивность

Поддерживаются десктоп (≥1180 px), планшет (≤1024 px) и мобильные (≤720 px, ≤480 px): бургер-меню, одноколоночные сетки, горизонтальная прокрутка фильтров, мобильные таблицы и формы.
